pi-comment-editor · V2

Review an assistant response like a code diff—without pretending it is one.

Build a native Pi line-range annotation UI. Borrow the interaction model from tuicr, but keep response review independent from VCS, persistence, and an external binary.

Product review complete: native-only line-range review, raw source lines, exact quoted context, and no tuicr embedding were approved.

Recommendation

Native core, one interaction model

4 explorer passes agreed

The way forward

  • /comment opens a normal ctx.ui.custom() component.
  • A pure reducer owns source lines, selection, annotations, cancellation, layout mappings, and export.
  • A thin component owns raw keys, theme, terminal dimensions, rendering, and Pi's multiline Editor.
  • The existing external-editor workflow is removed rather than retained as a parallel mode.
  • Finishing only calls ctx.ui.setEditorText(); it never sends a user message automatically.

Why not embed tuicr?

Its useful ideas are portable; its implementation is not. The app is coupled to file paths, old/new sides, VCS diffs, persisted sessions, Ratatui, and forge review lifecycle.

Delivery

Four slices, each independently testable

  • 1. Pure contracts
    Reducer, ranges, annotations, output goldens
  • 2. Vertical path
    Browse, select, draft one annotation, finish
  • 3. Full lifecycle
    Multiple, overall, edit/delete, discard, hardening
  • 4. Migration
    Remove external path, docs, packed install
Every slice runs npm run check. The default command does not switch until the single-annotation path has passed a manual Pi TUI check.
